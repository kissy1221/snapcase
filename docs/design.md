# 証跡作ったったー リプレイス設計

旧版 `../evidence-shot`（v0.2.0、Python/tkinter、Windows 専用）を、Electron + React/TS で作り直す。
機能は同等に引き継ぎ、UI は旧版を踏襲せずに作り直す。

## 決定事項

| 項目 | 決定 |
|---|---|
| 対象 OS | Windows と macOS を正式対応。Linux はベストエフォート（X11 で動けばよい） |
| 操作 | GUI のみ。CLI（`--pdf`、セッション名の引数）とランチャ（.vbs / .cmd）は作らない |
| マウスでの撮影 | 3秒カウントを廃止し、ウィンドウ（と画面全体）のサムネイル一覧から選ぶ方式にする |
| データ互換 | `manifest.json` v3 と `images/` の構成を変えない。旧版のセッションをそのまま開ける |
| 開発環境 | Node と npm だけ。Docker は使わない（画面収録やグローバルホットキーなどホスト OS の機能に依存するため） |

## 機能の引き継ぎ

| 旧版 | 新版 |
|---|---|
| Ctrl+Alt+S でアクティブウィンドウを撮影 | 同じ。キーは設定で変更できる（macOS の既定は ⌃⌥S） |
| 自分のウィンドウは撮らない | 同じ |
| URL の自動取得 | macOS は `get-windows`、Windows は UI Automation（PowerShell）。どちらもベストエフォート。Linux は取得しない |
| 注釈（枠・吹き出し・テキスト・黒塗り・トリミング、色、元に戻す、全消し）とコメント | 同じ。注釈は画像に焼き込む（黒塗りした元の値を残さない） |
| 画像ファイルの取り込み | ファイル選択に加えて、貼り付けとドロップでも追加できる |
| テストケース（ID・項目名・フォルダ・分類・前提条件・手順・期待結果・判定・備考） | 同じ |
| 並べ替え（ドラッグ＆ドロップと ↑↓、フォルダ単位での移動） | 同じ（ドラッグ＆ドロップとキーボード） |
| 記録とブロック7種（画像・コード・表・期待/実際・メモ・バナー・参照リンク） | 同じ |
| 番号の振り直し（削除や並べ替えで欠番が出ない） | 同じ |
| 直前の記録の取り消し | 保存後のトーストと、コマンドパレットから実行する |
| 実施情報（実施者・実施日・OS/端末・ブラウザ・対象ビルド・備考。既定値を自動入力） | 同じ。「概要」ページで入力する |
| CSV / Excel からの取り込み（列名の別名、判定の表記ゆれ、UTF-8 / Shift-JIS） | 同じ。ファイルのドロップでも取り込める |
| HTML（単一ファイル）・MD・PDF・XLSX 出力。目次、フォルダ見出し、しおり、ページ番号 | 同じ。PDF は Electron の `printToPDF` で作るので Edge / Chrome に依存しない |
| 終了時に PDF を自動で書き出す | セッションを閉じるときに自動で書き出す（形式は設定で選ぶ。既定は PDF と Excel） |
| 環境変数 `EVIDENCE_NOANNOTATE` / `EVIDENCE_BROWSER` | 前者は設定の「撮影後に編集画面を開く」に置き換える。後者は不要 |

## アーキテクチャ

### 技術スタック

- ビルド：electron-vite
- 配布パッケージ：electron-builder（Windows はインストーラと単体 exe、macOS は dmg、Linux は AppImage）
- UI：React、TypeScript、素の CSS（トークンは CSS 変数）。ダイアログはネイティブの `<dialog>`、コマンドパレットとトーストは自作（数十行）。Tailwind・shadcn/ui・アイコンライブラリは、必要が出るまで入れない
- 追加する依存
  - `get-windows`：最前面ウィンドウの ID・タイトル・範囲・プロセス、macOS では URL も取得する
  - `exceljs`：xlsx の出力と、xlsx の取り込み
  - `@fontsource/ibm-plex-sans-jp`、`@fontsource/ibm-plex-mono`：UI のフォントの同梱
- 使わないもの
  - 注釈ライブラリ：Canvas 2D の描画関数を1つ書き、画面表示と焼き込みの両方で使う
  - ドラッグ＆ドロップのライブラリ：HTML5 標準の機能を使う
  - 状態管理ライブラリ：`useSyncExternalStore` で足りる
  - iconv：Node 標準の `TextDecoder('shift_jis')` を使う
  - CSV のライブラリ：引用符と改行に対応した解析を `shared/import.ts` に書いた
- テスト：vitest（`npm test`）。対象は `shared/` の更新処理と解析、セッションの読み書き、取り込み、4形式の書き出し。画面の通し確認は Playwright（`_electron`）で行った

### プロセス構成

```
src/
  shared/    types.ts（manifest v3 の型）、ops.ts（manifest を更新する純粋関数）、constants.ts
  main/      index.ts（ウィンドウ、ホットキー、IPC）、session.ts（読み書き、旧形式の変換）、
             capture.ts、import.ts、export/（html, md, pdf, xlsx）
  preload/   index.ts（contextBridge で型付きの API を公開する）
  renderer/  ホームとワークスペース（同じウィンドウで切り替える）、編集画面（別ウィンドウ）、
             ウィンドウ選択
```

- manifest は main が一元管理する。メイン画面と編集画面の両方がデータを変更するため。
- renderer は `api.apply(op)` を呼ぶ。main は `ops.apply(manifest, op)` を実行し、保存してから全ウィンドウに `manifest:changed` を通知する。
- 画像は独自プロトコル（`evidence://`）で renderer に渡す。`contextIsolation` を有効にし、`nodeIntegration` は無効にする。
- log.html と log.md は、変更があるたびにデバウンスして作り直す。PDF と xlsx は書き出すときだけ作る。

### 撮影の流れ

1. ホットキーを押す。
2. `get-windows` で最前面のウィンドウを特定し、`desktopCapturer` で同じ ID のウィンドウを撮る。自分のウィンドウなら撮らずに警告する。
3. 対象があったディスプレイに編集画面を開く。URL の取得は裏で進め、取得できたら編集画面に表示する。
4. 保存すると、renderer が Canvas で注釈を焼き込んだ PNG を main に渡す。main は `images/NNNN.png` を書き込み、証跡を追加する。
5. 編集画面を隠す。フォーカスが元のアプリに戻るので、テストをそのまま続けられる。

マウスで撮るとき（撮影ボタンを押したとき）は、ウィンドウ選択の一覧から撮影対象を選ぶ。そのあとは手順 3 以降と同じ。

### 保存場所

既定は `<書類>/証跡作ったったー/<セッション名>/`。設定で変更できる。
中身は旧版と同じ（`manifest.json`、`images/`、`log.html`、`log.md`、`log.pdf`、`log.xlsx`）。

### OS ごとの注意点

- macOS：「画面収録」の許可が必要。初回起動時に許可を案内する画面を出す。社外に配るには署名と公証が必要。
- Windows：署名なしで配ると SmartScreen の警告が出る。
- Linux：最前面ウィンドウの撮影は X11 でのみ動く。Wayland では OS 標準の選択ダイアログで代用する。

## UI/UX 方針

モック：[mockup.html](mockup.html)

### 考え方

旧版の画面構成は引き継がない。
テスト担当者の作業は「テストケースを開く → 対象のアプリで操作する → 撮る → 判定する → 次へ」の繰り返しなので、この流れで迷う箇所と手数を減らす。

1. **開いているテストケースに撮影する。** 旧版の「選択中」と「撮影先」を1つにまとめる。緑のバナーと「撮影先にする」ボタンは作らない。保存先を間違えたときは、編集画面の「保存先」で直せる。
2. **撮影ボタンが撮影先を示す。** 画面下部に固定したシャッターボタンに「TC-003 に撮影」と表示する。画面で目立たせる要素はこのボタンだけにする。
3. **ダイアログを出さない。** 判定はセグメントボタンを1クリックで切り替える。項目はその場でクリックして編集する。テストケースを追加したときも、ダイアログではなくページがそのまま開く。
4. **概要ページが出力の表紙に対応する。** サイドバーの「概要と実施情報」は、実施情報と進捗を表示する。書き出した証跡の表紙（実施情報と目次）と同じ構成にする。
5. **テスト中は小さくして手前に置ける。** ウィンドウを細くするとコンパクト表示に切り替わる。表示するのは、開いているテストケース、判定、撮影ボタン、前後のテストケースへの移動だけ。
6. **すべての操作をキーボードでも実行できる。** ⌘K / Ctrl+K でコマンドパレットを開く。

### 画面

| 画面 | 内容 |
|---|---|
| ホーム | 最近のセッションの一覧（件数と判定の割合を積み上げバーで表示）と、新規作成の入力欄 |
| ワークスペース | 左はフォルダ別のテストケース一覧と進捗、右はテストケースのページ（項目と証跡のタイムライン） |
| 編集画面 | 暗い背景で画像を主役にする。上部に保存先・ツール・色、下部にコメントと取得元（タイトル、URL） |
| ウィンドウ選択 | 開いているウィンドウと画面全体をサムネイルで並べ、クリックで撮影する |
| 書き出し | 形式（HTML / PDF / Excel / Markdown）を選んで書き出す。選んだ形式は記憶する |
| 設定 | ホットキー、保存場所、撮影後に編集画面を開くかどうか、閉じるときに書き出す形式 |

証跡は「番号・コメント・時刻」を見出しにして、その下にブロックを並べる。
新しい証跡はタイムラインの末尾から追加する。既存の証跡へのブロックの追加は、各証跡の「•••」メニューから行う。

### デザイントークン

| 名前 | 用途 | ライト | ダーク |
|---|---|---|---|
| 墨 | 文字 | `#1C2230` | `#E7E9EE` |
| 紙 | アプリの背景、サイドバー | `#F3F4F6` | `#1E2127` |
| 面 | ページ | `#FFFFFF` | `#262A32` |
| 罫 | 境界線 | `#E2E5EA` | `#343944` |
| 藍 | 撮影ボタン、主な操作、フォーカス | `#2C4BB8` | `#7F8CFF` |

- 判定の色：OK `#1F8A5B`、NG `#D2372F`、保留 `#C98A12`、未実施 `#B3B9C5`。藍はどの判定の色とも重ならない。
- 判定は塗りのバッジ、分類は枠線だけのバッジで表す。軸が違うことが形で分かる。
- 書体：UI は IBM Plex Sans JP（アプリに同梱）、コードは IBM Plex Mono を使う。数字は tabular-nums（等幅数字）にする。
- 書き出す証跡の書体：BIZ UDPゴシック。Windows 10 以降に最初から入っているので、フォントを埋め込まずに済む。macOS ではヒラギノで代用する。
- 角丸は階層ごとに変える：ウィンドウ 10px、ボタン 6px、撮影ボタンは完全な円。影は、浮いている撮影ボタンとポップオーバーにだけ付ける。
- 動き：撮影して保存した証跡がタイムラインに追加されるときだけ動かす。`prefers-reduced-motion` の設定を尊重する。


## 実装状況（2026-09-27）

設計した機能はすべて実装した。旧版から変えた点と、確認できていない点を記す。

### 旧版から挙動を変えた点

- 直前の取り消しは「番号が最大の記録」を消す。旧版は「最後のテストケースの最後の記録」。並べ替えたあとでも、最後に撮ったものが消える。
- テストケース ID の採番は、既存の最大番号+1 にした。旧版は件数+1 で、削除のあとに重複した。取り込み・追加で ID が重なったときは `-2`, `-3` を付ける。
- 列見出しの認識は、完全一致を先に判定する。旧版は英語の `note` を別名 `no` の部分一致で ID 列と誤認した。
- PDF のフッタは、ページ番号（n / 全体）だけを出す。旧版は Edge / Chrome の既定で `file://` のパスと日付が出た。

### 確認できていないこと

実機での撮影は画面収録の許可が必要なため、自動テストの範囲外になっている。

- ホットキーでの実ウィンドウの撮影、撮影ボタンからのウィンドウ選択（macOS / Windows）
- Windows 全般（開発機は macOS）。特に、アドレスバーの URL を PowerShell の UI Automation で読む処理、タイトルバーの操作ボタンの重なり、インストーラの生成
- Linux
- macOS の署名と公証（未署名のまま。配布方法は未決）
- 編集画面を閉じたあと、元のアプリにフォーカスが戻ること（macOS は `app.hide()` で戻す想定）
